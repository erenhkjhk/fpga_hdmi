## 厂商模型实测结论

实际编译并执行了TD的受保护模型，没有自行替代七项IP的行为。

| 对象 | 实测结果 |
|---|---|
| 三种 RAM | 地址在第一个有效上升沿采入，第二个上升沿后输出该地址的数据；下游寄存器在第三个边沿采样 |
| RAM复位 | 高有效同步；边沿前输出不变，复位边沿后输出0；存储内容保留；测试中 `cea=0` 时复位输出也归零 |
| 四种 ROM | 同步高有效复位、两拍输出；每个地址的第一拍仍为上一地址数据，第二拍匹配参考 |
| ROM资源 | 字库和Logo各8192字、窗函数和旋转因子各256字，全部地址与资源文件逐字一致，复位后初始化数据仍在 |
| Soft FIFO | 实际容量1023字；普通模式的 `re` 在采样边沿触发读出，边沿后 `valid/dout` 有效，下游下一边沿消费；两侧reset-done握手、满/空状态及1023字顺序均通过 |
| PLL | 实际150/125/25 MHz；SDRAM两输出互为180°；复位清除锁定，释放后可重新锁定 |

RAM输出复位不代表内部所有读流水级或存储被清空。复位释放后的首拍可能出现复位前地址的数据；本设计依靠外层valid清空和完整的读延迟隔离它，不能把释放后的第一拍当成新请求结果。

## 发现及修复

1. **ROM初始化格式适配。** 直接将生成wrapper中的 `.mif` 文件名交给EG4仿真模型，四份ROM输出均为X。对同一旋转因子做三路对比：`.hex` 为X、`.mif` 为X、配套 `.mif.dath` 正确读出 `7FFF0000`。脚本因此生成四个仿真wrapper副本，仅将INIT_FILE转到对应 `.mif.dath`；其余结构、端口和参数保持原样。完整逐字比对随后通过。原 `al_ip` 生成文件、MIF和DATH资源未改写。
2. **Verilog/SV编译模式。** 生成PLL的动态配置端口名 `do` 是SystemVerilog关键字。厂商和工程 `.v` 按Verilog编译，测试平台 `.sv` 按SystemVerilog编译，随后编译通过。
3. **测试平台采样竞态。** 修正了测试驱动在ready刚变高时提前撤回valid、以及测试侧在时钟边沿立即更换文件字节等竞态。请求改为等待实际采样边沿；这些修改没有改动功能RTL，也没有放宽数据或时序断言。
4. **可靠判定失败。** ModelSim在 `$fatal` 后可能返回进程退出码0；脚本同时要求出现PASS标记且日志无Fatal/Error，避免将失败误判为通过。

已完成覆盖内尚未发现需要修改功能RTL的错误。不能将此结论外推为未测试场景、综合时序或上板结果均已通过。

## 集成仿真的边界

- 存储仲裁测试在SDRAM**应用接口**提供读写、延迟和刷新响应模型。它验证扩展RTL的数据、地址、事务排他、刷新预算及供数能力，不是SDRAM芯片引脚的电气/时序验收。
- FAT32集成在**扇区传输接口**注入FAT卷，实际运行FAT解析、两个扇区缓存、仲裁及WAV解析。它没有把完整SPI卡模型与BMP、WAV、物理SDRAM及HDMI同时串成一条端到端存储播放测试。
- 顶层烟雾测试另外加载真实SDRAM和HDMI加密核，但采用无卡输入；它检验顶层启动和协议锁定，不承担TF图片与音乐数据的端到端正确性证明。
- 转场系数扫描用提前发出帧请求缩短等待，每点比较128个像素；另一个STREAM用例才执行完整像素流和实际25 MHz消费速度。音频环从最后一个对齐块开始，以验证回绕而无需先填充262144字。
- 厂商模板的可选端口未连接及PLL动态配置端口宽度提示保留在日志中，没有屏蔽。活动端口由数据、容量、复位及顺序断言检查。

本轮没有进行综合、布局布线、时序收敛或上板验证；没有处理工程登记及引脚约束。

复现入口：`sim/modelsim/run.ps1 -All -Rebuild`。运行配置和边界详见 `sim/modelsim/README.md`；原始结果位于 `sim/modelsim/results/*.log`，机器汇总由 `collect_results.py` 生成。
