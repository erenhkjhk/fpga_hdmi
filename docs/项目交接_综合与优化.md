## 3. 数据通路和时钟

视频路径：SPI TF → FAT32 图片上下文 → BMP 解码/双线 RAM 缩放 → 异步 FIFO → SDRAM 双帧区 → 分块渐变 → 视频 FIFO → OSD/亮度/对比度/频谱合成 → HDMI 协议核 → ODDR 串行 PHY。

音频路径：同一个 SPI 控制器 → FAT32 音频上下文 → WAV PCM → 异步 FIFO → SDRAM 环形缓冲 → 播放 FIFO → 48 kHz PCM 提交 → HDMI 音频包。实际提交的左声道样本同时经邮箱送往 50 MHz 域做 DFT，再将整组柱高送到像素域。

| SDC 时钟 | 实际 PLL 输出 | 频率/相位 | 主要用途 |
|---|---|---|---|
| `clk_50m` | 板载输入 `clk_50m` | 50 MHz，0° | TF/FAT、解码、缩放、控制、DFT |
| `clk_sdram` | `u_pll_sdram/pll_inst.clkc[0]` | 150 MHz，0° | SDRAM 调度与帧/音频缓冲 |
| `clk_sdram_180` | `u_pll_sdram/pll_inst.clkc[1]` | 150 MHz，180° | 合封 SDRAM 接口时钟 |
| `clk_hdmi_serial` | `u_pll_hdmi/pll_inst.clkc[0]` | 125 MHz，0° | TMDS DDR 串行发送 |
| `clk_pixel` | `u_pll_hdmi/pll_inst.clkc[1]` | 25 MHz，0° | 640×480 视频、合成与音频提交 |

TD 报告把 SDRAM 周期显示为 6.666 ns，因此频率栏可能显示 150.015 MHz；这是报告精度，不是更改了 PLL 配置。`constraint_inspect.log` 已记录工具实际推导的 180°。

SDRAM 使用合封 `EG_PHY_SDRAM_2M_32`，没有需要分配 BGA GPIO 的外部 SDRAM 顶层端口。存储地址单位为 32 位字：

| 区域 | 起始字地址 | 字数 |
|---|---:|---:|
| 图 0 | `0x000000` | 307200 |
| 图 1 | `0x04B000` | 307200 |
| 音频环 | `0x100000` | 262144 |

音频左右声道分别占一字，低 24 位为样本，bit31 为声道标记。默认音频低水位 96000 字，高水位/预缓冲 192000 字。SDRAM 每事务 64 字，四字对齐，读写切换和刷新前有排空；转场期间两帧区锁定。优化后不能破坏事务所有权、音频连续性或帧区锁定。

真实厂商模型已经确认：

- 新增 RAM/ROM 为 SP、OUTREG；地址第一个有效上升沿采入，第二个上升沿后输出对应数据，下游寄存器在第三个边沿消费。
- `rsta` 高有效同步复位输出，RAM 存储内容保留。复位释放首拍不能当成新读请求的结果，必须依靠外层 valid 和读流水隔离。
- FIFO 为普通异步模式；`re` 被采样后输出 `valid/dout`，下游下一边沿消费。两侧 reset-done 和跨域就绪握手必须保持。
- 物理 SDRAM 实测 MRS 为 BL4、CL3、顺序突发。应用读请求第 10 周期后输出有效数据，下游第 11 周期消费；这两个描述是采样口径差异。
- 真实 PLL 的频率、SDRAM 180°、复位失锁及重新锁定已经单独验证。

生产 ROM 初始化文件分别在 `assets/osd/td_init/` 和 `assets/spectrum/td_init/`。生成 wrapper 使用相对 `al_ip` 的 `../assets/.../*.mif`；**TD 本轮已实际成功读取四份 MIF**，原文件不用改成 DATH。

ModelSim 的 EG4 模型只认配套 `.mif.dath`；脚本在 `sim/modelsim/build/ip_sources/` 生成只改初始化文件名的仿真 wrapper 副本。不能把这些副本登记进 TD。DFT ROM 使用 `.v` 的 `9K(FAST)` 配置；不要同时编译 VHDL 副本。生成 PLL 有名为 `do` 的端口，生产 `.v` 要按 Verilog 编译，不能全部强制 SystemVerilog。

### 已修复、优化时不能回退的问题

`rtl/storage/sd_sector_buffer.v` 原先只有一个 512 字节缓存项。在分散簇的 WAV 中，数据与重复 FAT 扇区来回替换，5 MHz SPI 平均带宽不够，曾在完整用例第 7232 对样本出现非预期静音。

现改为两个 512 字节缓存项、LBA 标签和 LRU 替换；每个文件上下文保留重复读取的 FAT 扇区。两个上下文合计只比旧版多 1024 字节推断 RAM，不需要新手工 IP。标签必须在整个扇区成功完成后发布，复位/错误失效。此修复后的真实 SPI 400 ms 吞吐测试跨 16 轮文件循环，无断供。

另修复的是测试端 HDMI 接收模型：活动视频中合法 RGB `AB55AB` 可产生与保护带相同码字，不能再当保护带丢弃。已有 640 像素定向回归。修复前日志留作失败证据，不计入 34 项通过数。

## 8. 建议接手顺序和优化边界

以下是基于现有源码/报告的候选方向，不是已经实施或保证收敛的方案。

1. **先保留基线，再同时规划面积与时序。** 读归档的 `gate.timing`、`gate.area`、`phy_run.log`，核对当前源码哈希。优先减少 MSlice 和 DSP 压力，不要先无计划地给所有长路径加寄存器导致面积继续上涨。
2. **BMP 几何与缩放坐标。** 保留完整头部合法性/文件大小校验；在通过校验后锁存有界尺寸，避免 32 位高度绝对值长期组合传播到像素计算。坐标商余数可考虑预计算、分拍或精确递增实现，必须保持端点对齐、12 位小数、边界夹取和既有舍入。不能直接换近似坐标或降低尺寸上限。
3. **双线性插值的 DSP 复用与流水。** 检查 14 个缩放 DSP 的实际位宽分解和使用时段；利用非实时加载链路的 valid/ready 允许分时运算。不能破坏单像素/单行、2048 边界、上下翻转、读 RAM 两拍延迟、取消/错误清空及恰好 307200 个有效输出。
4. **像素合成器。** 固定每像素吞吐要求，不能增加会阻塞有效视频的握手停顿。可以把低速数字转字形/除模运算移到状态更新时，或拆分 Alpha/调节流水；RGB、ROM 位选择、字形/Logo地址、坐标、帧状态、valid/user/last 必须同步延迟。保持亮度/对比度、图层顺序、帧中更新隔离和滚动行为。
5. **150 MHz 渐变通路。** 重点看块 RAM → 混合乘加 → FIFO 写入路径，评估拆拍/共享乘法器。增加的延迟必须进入 64 字块索引、FIFO 预留、事务排空和转场端点的计数，不能靠提前写出或多丢一字解决。
6. **DFT 和 FAT 的面积。** DFT 窗口采集与计算有时间复用空间；复用后要证明每 256 个实际样本的处理预算仍足够，结果与定点参考一致且无 overrun。FAT 双上下文面积大，可以研究有界宽度或共享只读几何，但必须保留图片/音频独立文件进度、音频低水位优先和现有双扇区缓存收益。
7. **再审查复位、CDC、厂商接口和约束。** 仅对网表确认的同步器首级/有效握手关系设置必要例外，不切掉整组时钟。对合封 SDRAM 路径先核对原厂文档、实际网表和 180°关系，再决定实现调整。
8. **按变更范围做回归。** 先跑相关模块和数值参考，再做存储吞吐/集成，最后需要时跑长端到端。功能基线保持后，依据新窗口任务安排 TD 综合与实现；每个候选记录面积、MSlice、各时钟组 WNS/TNS 及失败原因，避免只看全局单个 WNS。

不能删掉扩展、降低输出像素速率、去掉 WAV 连续播放、退回单扇区缓存或用静态图替代真实播放来减少资源。若确需改变可见行为、音频格式、时钟或用户手工 IP 参数，应把影响明确交给用户决定。
