# 五项扩展 RTL 集成说明

五项扩展已写入 `rtl` 并接入 `fpga_hdmi_top`，文件清单在 `rtl/sources.f`。初版静态检查之后，已继续执行指定ModelSim 2020.1的真实厂商模型、模块及应用接口集成仿真，最新结果见 [ModelSim仿真报告](扩展1至5_ModelSim仿真报告.md)。尚未进行综合、布局布线或上板验证。

## 厂商接口核对与证据边界

核对对象是 `al_ip` 中的实际 Verilog，不是截图推测或替代 IP。行缓存名字为 **`ram_scale_line1`**，两份实例均引用该定义。

| 实际模块 | 位宽 × 深度 | 本次实例数 | 用途 |
|---|---:|---:|---|
| rom_osd_font | 8 × 8192 | 1 | ASCII 8×16、中文 16×16 |
| rom_anlogic_logo | 16 × 8192 | 1 | 128×64 ARGB4444 Logo |
| rom_dft_twiddle | 32 × 256 | 1 | 高16位 cos，低16位负 sin，Q15 |
| rom_dft_window | 16 × 256 | 1 | Hann Q15 |
| ram_scale_line1 | 24 × 2048 | 2 | 两行源图 |
| ram_blend_block | 24 × 64 | 2 | 新旧图块 |
| ram_audio_window | 24 × 256 | 2 | 采样与 DFT 交替使用 |

已有 `fifo_pixel_async` 定义复用为四份独立实例，新增两份分别服务音频写入与播放；PLL 保持实际 150 MHz/180°、25 MHz、125 MHz 配置。没有改写任何生成的 IP 文件，也不需要新增 IP 定义。

以下为初版RTL设计时的静态依据，动态实测结论及ROM初始化适配以最新仿真报告为准：

- `D:/TD/arch/eagle_macro.v` 的 `EG_LOGIC_BRAM` 声明，确认 `RESETMODE` 默认值为 `SYNC`。三种 RAM 显式设置该参数；四种 ROM 使用这个默认值。所有新增 IP 均为 `OUTREG`，内部 `ocea=1`。
- `D:/TD/ip/depot/AXI_Ethernet_Lite_1.0/AXI_Ethernet_Lite/RTL/ram_infer.v` 是 TD 随附的可读 RAM 参考实现：第一级同步读、第二级输出寄存器；复位输出寄存器，不遍历清空存储数组；存储读使能与输出寄存器使能独立。
- `D:/TD/sim_release/eg4/eg_logic_bram.v`、`eg_phy_bram.v` 和 `eg_phy_bram32k.v` 的行为主体受保护。初版没有执行它们；后续已使用指定的ModelSim 2020.1直接执行真实模型，确认同步复位、两拍读取、复位保留存储内容，并完成全部ROM地址比对。详细动态结果见最新仿真报告，没有解密或自行替代模型。

本次采用的接口契约：地址在第一个有效上升沿采入，第二个上升沿后 `doa` 对应该地址；下游寄存器在第三个边沿采样它。`rsta` 高有效同步复位输出，不依赖 RAM 内容复位；写周期读出值不参与运算。各消费者保持 `cea=1`，复位期间禁止 `wea`，外层 valid 同时清空，复位后必须先填充 RAM 才允许消费。没有依赖 `cea=0` 时的内部复位优先级或输出数值。

四份 ROM 初始化仍指向原 `assets/.../td_init/*.mif`，配套 `.mif.dath` 保持原样。生成文件的相对路径以 IP 所在 `al_ip` 为基准。ModelSim实测需使用对应 `.mif.dath`，仿真脚本仅在build内的wrapper副本重定向初始化文件名，原生成文件保持原样；TD工程的生产初始化路径仍需在后续工程导入时确认。DFT 的 Verilog 显式选择 `9K(FAST)`；本清单只导入 `.v`，不混入省略该设置的 VHDL 副本。

### 视频与缩放

缩放按端点对齐公式 `sx=x*(W-1)/639`、`sy=y*(H-1)/479`，坐标保留12位小数。水平、垂直插值保留中间精度，最后统一舍入。源图始终按文件顺序读入，相邻行按行号奇偶存储；同一行可反复用于放大，无需整幅源图缓存。正高度 BMP 的输出行序由既有 SDRAM 写入器翻转。

640×480 输出不在有效行中停顿。合成器从 AXIS 的帧首、行尾及 valid 重建坐标，字库位索引、RGB、Logo区域及 user/last/valid 与两拍 ROM 延迟一致，最后增加一级合成输出。HDMI ready 的协议诊断移到合成后的接口。

图层顺序：照片亮度/对比度 → 75% Alpha频谱 → 信息背板 → Logo → 文字。文字全局 Alpha 参数 `TEXT_ALPHA` 默认15，Logo使用每像素4位Alpha。时间位于(8,8)，Logo(504,8)，音源标签y=344，参数/状态/图片序号y=368/388/408，标语y=456。标语每两帧左移一像素。

拨码 `{sw[1],sw[0]}` 对应 0、+32、−32、+64；`{sw[3],sw[2]}` 对应1.00、1.25、0.75、1.50倍。顶层新增 `sw[3:0]`，`SWITCH_ACTIVE_LOW` 可按板卡极性设置。四个按键的功能维持原定义。

转场开始前必须完整写入并校验新图；转场期间两帧区均锁定。帧请求时更新混合系数，整帧不变。首张有效图直接显示；后续从旧图权重100%开始，最终切到新图的精确像素，再通知轮播控制器。五秒停留从这个通知之后计时。

### 存储和 WAV

两个 FAT32 读取实例各保有文件链进度及512字节扇区缓存，共用一个 SPI 控制器。为复用已存在的文件系统逻辑，卷几何寄存器也各保留一份；没有改成共享几何数组。仲裁只在整个扇区完成后换所有者，音频低水位优先，否则双方等待时轮换。

图片仍按根目录 BMP 索引打开；音乐只匹配短文件名 `BGM     WAV`。支持48 kHz、24位、双声道、格式码1 PCM，检查 ByteRate=288000、BlockAlign=6、RIFF边界、chunk长度和data长度整除6。未知chunk及奇数字节填充可跳过。缺失或不支持的音乐退回原 I2S 测试音；OSD显示 `TONE`、`WAV` 或 `WAV BUFFER`。

首次读取 data 第一个字节时，FAT32层记录簇号、簇内扇区、扇区内字节偏移和data长度。播放完该data段直接恢复书签并重读起始扇区，继续跟随 FAT 链；不重扫目录、不反复解析文件头、不把尾部chunk当音频。64字块的不足部分自然接上下轮样本，不补音频零字。

SDRAM地址单位均为32位字：

| 区域 | 起点 | 字数 |
|---|---:|---:|
| 图0 | 0x000000 | 307200 |
| 图1 | 0x04B000 | 307200 |
| 音频环 | 0x100000 | 262144 |

PCM左右声道各占一字，bit31为声道标记，低24位为样本。音频环按64字块提交，只有事务和排空完成后才更新占用量与指针。读写、转场及刷新仍由同一个仲裁器互斥管理。

预缓冲阈值192000字，低水位96000字，高水位192000字；高水位暂停接收新的左声道字，已接受的右声道允许收尾。播放FIFO预留足够整块空间才发起64字读事务。缺数时输出静音并要求重新达到预缓冲阈值；重新缓冲会主动请求补充，避免在高低水位之间停住。图片加载、切换和转场均不会复位音频FIFO或环指针。

48 kHz提交节拍沿用原内部 I2S 音源/接收器的分数节拍，播放模块在该节拍选择 WAV、静音或测试音。音频使能跟随 `video_locked`，不再跟随“正在显示图片”。ACR继续使用实际25 MHz对应的N=6144、CTS=25000。

### 频谱

实际提交给 HDMI 的左声道样本经24位邮箱送到50 MHz域，窗口乘 Hann 后写入两份 `ram_audio_window`。一份采集，另一份计算；计算未结束时不交换缓存，并置 overrun，不能覆盖正在计算的窗口。

计算256点DFT的0..127频点，一个24×16有符号乘法数据通路分时计算实部和虚部，48位累加；归一化后计算平方能量。每四频点归一柱，第一柱排除直流，39位组能量转对数高度并限制在120像素。整组256位高度经邮箱发布，视频帧边界做下降平滑和峰值保持。

当前状态机每个采样项5拍，加每频点3拍收尾，约164224个50 MHz周期，即3.285 ms；这是源码时序预算，不是仿真测量或时序收敛结论。采样一窗需要5.333 ms。乘法器、常数除法和视频合成的实际资源与频率仍需后续综合确认。

## 本轮检查及后续边界

`tools/check_extension_rtl.ps1` 使用 Icarus 的 `-t null` 做 Verilog-2005 语法与端口展开，不执行 `vvp`。先检查未解析模块仅有已有加密HDMI、SDRAM和Soft FIFO三个实现，再用真实公共wrapper和TD原语声明完成静态展开。生成IP的隐式悬空网、黑盒导致的端口方向提示及数组敏感列表提示不代表功能验证。

初版静态检查通过，后续动态仿真记录另见上述报告。工程登记文件 `project1.al` 保留用户已有修改；本次没有处理工程登记，也没有新增拨码引脚约束。后续需要把新增顶层拨码端口接到板卡实际管脚，并在TD中以正确文件清单和顶层做工程验证。

初版列出的动态验证计划如下；现已完成的用例见最新仿真报告，不应把这段历史计划当成仍未执行的项目：EG4模型的同步复位与两拍输出；单像素/奇数宽/上下翻转BMP；跨扇区和跨簇的WAV data书签；非64字整数长度的循环接续；渐变端点及刷新占用；播放缺数恢复；DFT单音频点、左右声道标记；最终资源、时序和ROM初始化加载。综合时序、布局布线及上板仍属后续工作。
